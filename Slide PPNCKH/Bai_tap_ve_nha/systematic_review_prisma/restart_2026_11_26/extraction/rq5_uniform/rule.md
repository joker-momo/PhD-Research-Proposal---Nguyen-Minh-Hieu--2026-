# HK261 RQ5 uniform quantitative extraction rule

Version 1.0. This is a post-protocol rule fixed for the editorial reread before accepting any results under it. The starting manuscript checkpoint is `ff1cf4b`. The 46 approved reports represent 46 studies. Pending and unretrieved records and the original screening and appraisal decisions are outside this pass.

## Outcome boundary

Read each report's evaluation/results and follow the references to relevant setup, tables, figures and appendices. Include outcomes of the evaluated collaborative system or a component explicitly used by that system for any of the six RQ5 domains. Use the measurement boundary stated in the report.

- **Latency** includes end-to-end time, processing or transfer time, inference speed, throughput or frame rate.
- **Energy** includes energy or power with its original measurement boundary.
- **Communication** includes transmitted data, traffic, packet delivery, or communication overhead. A configured channel rate is a condition.
- **Accuracy** includes model or task quality, with the task and metric named. Mark task success separately from accuracy of the neural model.
- **Reliability** includes service completion, deadlines, failures, coverage or recovery when explicitly evaluated as service outcomes. A configured failure rate is a condition.
- **Scalability** covers a result evaluated across expressly different workload or system scales. Preserve the underlying metric and scale. Count its effect once if it also belongs to a primary domain.

Limit the inventory to the collaborative system or its directly evaluated components. Mark standalone component profiling, modeled/analytical values, simulations, emulation, physical results and mixed modalities explicitly. Exclude hyperparameters, setup-only values, resource budgets without a measured result, cited results from other investigations, purely qualitative assertions, and objectives with no separately interpretable RQ5 outcome. Count a composite objective explicitly as composite if its underlying quantities cannot be separated. Never treat a relative improvement as a percentage-point difference unless the report explicitly defines it that way.

## Selection and transcription

Review every results block for each report using the same rule. Preserve the source blocks and any exact-value gaps. For the report-level comparative inventory, extract the first eligible explicitly numerical result by original body reading order in each RQ5 domain where available. An eligible exact result has a named metric, original value with unit or dimensionless scale, an identifiable evaluated method, and a source-bounded scenario. Preserve any named comparators and their exact values in the same result block where the authors make that comparison. Record different explicitly stated scenarios separately whenever the selected result has multiple comparisons. A qualitative or plotted result never displaces an eligible exact result. If a useful condition or denominator is not specified, record that it is unreported and describe the resulting ambiguity. Record uncertainty as printed and label whether the report defines it. When a repeated value occurs in several places, cite the primary table/figure and use nearby text as a secondary locator. Preserve additional eligible outcomes in the source-block inventory; the numeric table is a fixed anchor per domain, not a census of every table cell or operating point.

An exact numeric result must be stated in body text or visibly printed in a table, graph label or caption. Preserve approximation, bounds, ranges, sample size and uncertainty without adding precision. Curves without exact data labels are plot-only. Keep them and incomplete or inconsistent conditions in the source-block index without estimating points. When a quantitative value or condition remains unresolved after checking the relevant pages, record it explicitly and keep it outside verified comparisons. An inaccessible or unreadable report cannot pass coverage. A report with readable results and no eligible exact result can pass with a checked source locator and reason.

Record report and study ID, repository-relative PDF path and SHA-256, physical PDF page from 1, stable section/table/figure label, an original excerpt or printed row, metric and unit, outcome literal, method, comparator status and values as reported, workload, conditions, modality, and synthesis eligibility. A source block with multiple domains may be cited under several domains. Reconcile reports once against the accepted corpus. Compare only within the same reported workload and conditions and report count denominators by study. Avoid pooling or cross-study winner rankings. Verify every numerical value and comparator adopted by RQ5 against the original PDF, and record ambiguous cases with locators and reasons. Headings and automatically located excerpts are aids for the human-readable audit.

Report completeness by access, source blocks screened, availability of exact values, checked plot-only evidence, and unresolved evidence. Only update RQ5 when all 46 PDFs have a reviewed, source-located entry or an explicit and supported reason. The prior 67 rows may help locate evidence. Those rows and the new anchor counts represent different selection rules and cannot be subtracted as estimates of primary outcome availability.
